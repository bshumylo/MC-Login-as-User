# Login as User

**Дозволяє адміністратору EspoCRM увійти як інший користувач, наприклад щоб побачити, що бачить цей користувач, і налагодити права доступу.**

[English](README.md) · Українська

Версія **1.0.2** · EspoCRM **≥ 10.0.0** · PHP **≥ 8.3** · AGPL-3.0

## Що це робить

- **Один клік.** Відкрийте запис користувача й оберіть **Login as User** у меню дій. Ви бачите EspoCRM саме так, як її бачить цей користувач.
- **Легко повернутися.** Поки ви працюєте як інший користувач, на екрані лишається банер *Acting as …* з кнопкою **Return to My Account**. Пункт **Вийти** в меню користувача також стає **Return to My Account**.
- **Зручно для перевірки ACL.** Перевіряйте ролі, команди й доступ до полів, не питаючи пароль.
- **Зрозумілі записи.** Ваші дії зберігаються від імені цього користувача (створив, змінив, стрічка). Записи Action History зберігають посилання на ваш власний вхід.
- **Слід у журналі.** Початок і ручне завершення кожної сесії (хто, як хто, IP-адреса) записуються в журнал EspoCRM.
- **Обмеження в часі.** Сесія сама завершується через одну годину (це можна змінити).
- **Три мови.** Англійська, українська та чеська.

## Вимоги

- EspoCRM 10.0.0 або новіша.
- PHP 8.3 – 8.5.

## Встановлення

1. Завантажте `mc-login-as-user-1.0.2.zip` зі сторінки [Releases](../../releases/latest). Не беріть автоматичний файл «Source code (zip)»: його не можна встановити.
2. В EspoCRM відкрийте **Адміністрування → Розширення → Завантажити**, оберіть ZIP і натисніть **Встановити**. Інсталятор сам перебудовує систему. **Адміністрування → Rebuild** потрібен лише тоді, коли щось працює не так.
3. Налаштування не потрібні. Відкрийте **Адміністрування → Користувачі**, оберіть активного звичайного користувача й скористайтеся **Login as User** у меню дій (угорі праворуч у записі). Цей пункт бачать лише адміністратори.

## Оновлення

1. Зробіть резервну копію бази даних і файлів.
2. Встановіть новий ZIP поверх старого (**Адміністрування → Розширення → Завантажити → Встановити**).
3. Примітки до версій:
   - З версій до 1.0: старий cookie `login-as-user-id` видаляється автоматично й більше не використовується.
   - **1.0.2**: тепер можна обрати лише активних звичайних користувачів. Див. «Безпека».
   - Релізи 1.0.1 і старші мають теги без префікса `v`.

## Налаштування

Адмін-сторінки немає. Один необов'язковий параметр додається в `data/config.php`:

| Параметр | Типово | Що робить |
|---|---|---|
| `loginAsUserTtl` | `3600` (одна година) | Тривалість сесії в секундах. Допустимий діапазон: від 60 до 28800; значення поза діапазоном підтягується до найближчої межі. |

Приклад: `'loginAsUserTtl' => 1800,`

Щоб завершити сесію раніше, натисніть *Return to My Account* або вийдіть із системи.

## Безпека

- **Лише адміністратори, лише звичайні користувачі.** Діяти можна лише як активний звичайний користувач, за тим самим правилом, що й у вбудованій функції EspoCRM. Не можна діяти як ви самі, як адміністратор чи суперадміністратор, а також як portal-, API-, системний або неактивний користувач. API-користувачі не можуть почати сесію. Правила перевіряються під час старту сесії та на кожному запиті.
- **Підписаний квиток, а не простий cookie.** Запит на старт створює cookie **HttpOnly**, підписаний `cryptKey` вашого інстансу. Він містить адміністратора, цільового користувача, auth token поточної сесії та термін дії. Його не можна підробити, повторно використати після виходу чи в іншій сесії або прочитати зі скриптів. Недійсні квитки ігноруються.
- **Обмежено в часі.** Типово одна година (див. «Налаштування»).
- **Журналюється.** Початок і завершення записуються в журнал на рівні `warning`, тому рядки зберігаються за типових налаштувань журналу.
- Користуйтеся цим лише з відома команди й лише коли це потрібно. Усе, що ви робите, записується від імені іншого користувача.

Щоб повідомити про вразливість, див. [SECURITY.md](SECURITY.md).

## Для розробників

**Локальна збірка ZIP.** Розширення використовує офіційний шаблон.

```bash
npm ci
node build --extension   # створює build/mc-login-as-user-<version>.zip
```

**Релізи.** Підвищте версію в `extension.json` і `package.json` та злийте зміни в `main`. Workflow [.github/workflows/release.yml](.github/workflows/release.yml) сам створить реліз `vX.Y.Z` з `mc-login-as-user-X.Y.Z.zip`. Той самий workflow використовується в усіх репозиторіях розширень MC. Історію змін див. у [CHANGELOG.md](CHANGELOG.md).

**Технічні нотатки.** Endpoint-и старту й зупинки: `POST /api/v1/LoginAsUser/start` і `POST /api/v1/LoginAsUser/stop`. Запит на старт приймається лише з auth token поточної сесії. Код розміщено в `src/files/custom/Espo/Modules/LoginAsUser/`; unit-тести — у `tests/unit/` (`npm run unit-tests`).
